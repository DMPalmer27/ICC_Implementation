2 Background
2.1 Motivation for the ICC Scheme
The proliferation of artificial intelligence and machine learning has fundamentally
transformed how data is handled. As model complexity and dataset scale continue to
grow, the computational demands have exceeded the infrastructure available to all but the
largest institutions. This has driven heavy reliance upon cloud computing services such
as Amazon Web Services, Microsoft Azure, and Google Cloud, for example, which offer
on-demand access to powerful computation power at a fraction of the cost of building
equivalent infrastructure. For many smaller companies and research institutions, such

2 Background 2
services are not just convenient but required to remain competitive.
Unfortunately, this reliance on external computation introduces tension regarding
data privacy. Using cloud computing generally requires uploading the raw dataset to
the service provider, exposing the data to an entity outside of the user’s control. For
organizations constrained by regulations such as HIPAA, or those whose competition
depends on their data being confidential, this exposure may be unacceptable. The result
is that privacy sensitive organizations are systematically excluded from the computational
resources that would allow them to take advantage of modern AI efficiency. Thus, there
is need for secure ways to use cloud computing to democratize the space.
The natural response is to encrypt the data before uploading it, and significant re-
search has gone towards analyzing just this. The standard approach, homomorphic en-
cryption (HE), instead incurs massive overhead and does not allow common learning
algorithms to be performed directly on the encrypted data [2]. Further, HE uses com-
putational rather than information-theoretic privacy guarantees. The scheme that I am
implementing takes an alternative approach grounded in information-theoretic security.
The goal is to encode data using a short random key such that the encoded version
provably leaks no information about any small subset of the original data, regardless
of the computational power of the adversary. This guarantee is formalized through the
notion of perfect subset privacy (PSP), which ensures zero mutual information between
the encoded data and anyr-element subset of the original whereris a tunable security
parameter. This notion of PSP kickstarted the line of three papers, each building off
of the last, which result in my implementation. Information-theoretic guarantees of the
kind that PSP gives are strictly stronger than the computational ones such as HE. They
hold unconditionally, without any assumption about the adversary’s resources.
Within this information-theoretic framework, prior work on privacy in distributed
computation has focused on protecting data held by the system administrator from ad-
versarial worker nodes inside the service provider. Crucially, this assumes that the system
administrator is fully trusted. This is problematic when the user wants privacy against
the entire service provider.
The scheme implemented in this project, introduced in [3] and extended to non-
uniform data in [1], addresses this gap by shifting the privacy barrier from the boundary
between the administrator and its workers to the boundary between the user and the

his entropy off of a key remark: “the entropy of a combined experiment consisting of the
performance of two independent experiments is equal to the sum of the entropies of these
two experiments.” Because I am drawing my sample data independently at random,
this greatly simplifies entropy calculation. By this additivity of R´ enyi entropy under
independence ((1.20) in [5]), applying it inductively toni.i.d. draws givesH p(X) =

function to calculate entropy through this shortcut calledcompute fast iid entropy.
It functions much the same ascompute p entropyexcept it computes the entropy over
the probability distribution that the data is drawn from rather than over the data itself.
Because allndata points are drawn independently, this can be accurately scaled up to
the entire dataset orr-subset by multiplying bynorrwithin the test cases.

5.1 Straggler Resilience via Information Super-Sets
The obvious next direction to take this implementation is to fully realize the ICC
scheme and implement straggler resilience via information super-sets. As previously
mentioned, a multisetT∈[n] is anS-information super-set if any (|T|−S)-subset ofT
contains an information set. This is given in Definition 4 in [3]. So, even ifSworkers fail
to respond, the remaining workers who do respond have evaluations on an information
set so their responses are sufficient for the client to decode the answer.
I have begun a first pass at information super-set generation through creating a
get information supersetfunction inutils.py. This function takes aGalois field
(GF), field sizeq, number of variablesm, maximum total degreed, and number of strag-
glersSas parameters. It returns a list which is the superset containing entries such that
any subset of sizeλcontain an information set. Inefficient describes this construction
too kindly; it brute-force builds the superset from the ground up by ensuring that no in-
variants are violated. It begins with the information set I have been relying upon which
is created by callingget information set. It then enumerates all possible points with
itertools.product. For each of these points, it checks if it is already in the superset and

full rank given this point was added. If this passes, the point is added.
While this is a highly inefficient construction, it serves as a good jumping off point to
expanding this scheme to tolerate straggling workers.
5.2 Case Study
As another part of my thesis I want to apply this ICC scheme onto a machine learning
dataset so this is one more future path for the project. I will take a dataset I want to
execute a learning algorithm on and follow the encoding, computation, and decoding
phases of this scheme instead of directly performing the learning algorithm on the data.
I will use a learning algorithm that can be accurately computed as a polynomial to
complete the entire learning stage as if the data has been encoded and offloaded to a
cloud environment.
The most interesting part of this case study will be analyzing the information leakage
bounds. I will explore how reliable they are, how consistent they are, and whether they
are meaningful enough to provide justification for this scheme being a competitive way
to train ML models securely without the computation power to do so on their own.
